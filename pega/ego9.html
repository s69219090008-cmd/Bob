การเขียนแบบภายใน (Internal Script)

  • รูปแบบ: พิมพ์โค้ดลงในแท็ก <script> วางไว้ก่อนปิด </body>
  • เปรียบเทียบ: โน้ตคำสั่งสั้นๆ แปะไว้บนตู้เย็น
  • การใช้งาน: เหมาะกับโค้ดขนาดเล็กที่ทำงานเฉพาะเจาะจงแค่หน้าเว็บเดียว

การเชื่อมไฟล์ภายนอก (External Script)

  • รูปแบบ: สร้างไฟล์ .js แยก แล้วเชื่อมด้วย <script src="main.js"></script>
  • เปรียบเทียบ: คู่มือการทำงานแยกเป็นเล่มต่างหาก
  • การใช้งาน: มาตรฐานมืออาชีพ โค้ดสะอาด นำไปใช้ร่วมกับหน้าเว็บอื่นๆ ได้ทันที

9.6 ตัวกระตุ้นการทำงาน (The onclick Event)
1
การกระทำ (User Action)
2
สัญญาณกริ่ง (Event Trigger)
3
ตอบสนอง (Function Execution)
  • 1. การกระทำ (User Action): ผู้ใช้งานกดคลิกปุ่มบนหน้าเว็บไซต์
  • 2. สัญญาณกริ่ง (Event Trigger): แอตทริบิวต์ onclick ทำหน้าที่เหมือนกริ่งประตู ส่งสัญญาณแจ้งเตือน
  • 3. ตอบสนอง (Function Execution): ปลุกชุดคำสั่ง JavaScript (Function) ที่เตรียมไว้ให้ตื่นขึ้นมาทำงานทันที
ตัวอย่างการปฏิบัติ: เปลี่ยนข้อความหน้าเว็บด้วยปุ่มกด

ล็อกเป้าหมายด้วย id แล้วเขียนทับข้อความด้วย .innerHTML เมื่อปุ่มถูกคลิก ลองกดปุ่มด้านขวาดูผลลัพธ์จริง

<h2 id="promo-text">กดเพื่อรับส่วนลด</h2>
<button onclick="getBonus()">รับส่วนลด</button>

// JavaScript
function getBonus() {
  document.getElementById("promo-text")
    .innerHTML = "ยินดีด้วย! คุณได้รับส่วนลด 50%";
}
กดเพื่อรับส่วนลด
9.7 ข้อจำกัดของ HTML5 และเหตุผลที่ต้องใช้ JavaScript
PROBLEM: ข้อจำกัดของ HTML5

ตรวจสอบได้แค่กฎพื้นฐาน (เช่น ห้ามเว้นว่าง, กำหนดค่าต่ำสุด-สูงสุด) แต่ไม่สามารถเช็กความซับซ้อนได้ เช่น รหัสผ่าน 2 ช่องพิมพ์ตรงกันหรือไม่

SOLUTION: ทางออกด้วย JavaScript

JavaScript (Custom Validation) ดึงข้อความที่กำลังพิมพ์ออกมาตรวจสอบด้วยเงื่อนไขอิสระ สร้างประสบการณ์ที่ลื่นไหลกว่า เปรียบเสมือนพนักงานรักษาความปลอดภัยสุดสมาร์ท

9.8 การรับรู้และดักจับพฤติกรรมผู้ใช้ (User Events)
onmouseover
onmouseout
onkeydown
onkeyup

Mouse Events

  • onmouseover (Mouse Hover): ทำงานทันทีเมื่อนำเมาส์ลากไปวางพาด (ยังไม่คลิก) ใช้ดึงดูดความสนใจ
  • onmouseout (Mouse Leave): ทำงานทันทีเมื่อลากเมาส์ออกจากวัตถุ ใช้คืนค่ารูปลักษณ์เดิม

Keyboard Events

  • onkeydown (Key Press): ทำงานในเสี้ยววินาทีที่กดปุ่มลงไป
  • onkeyup (Key Release): ทำงานทันทีเมื่อปล่อยนิ้วขึ้น เหมาะสำหรับการตรวจสอบข้อมูลแบบสดๆ (Real-time) ขณะพิมพ์
ตัวอย่างการปฏิบัติ: ระบบตรวจสอบรหัสผ่านอัจฉริยะแบบ Real-Time

ดักจับจังหวะปล่อยนิ้วจากการพิมพ์ (onkeyup) แล้วเรียกฟังก์ชันเช็กทันทีโดยไม่ต้องรอปุ่ม Submit ลองพิมพ์ในช่องด้านขวาดูผลลัพธ์จริง

}

.innerHTML — เปลี่ยนแปลงเนื้อหาหรือสีสันทันทีแบบ Real-time

สรุปท้ายบท: จากหน้ากระดาษนิ่ง สู่จักรกลที่มีชีวิต

บทนี้ว่าด้วย JavaScript สมองกลผู้เนรมิตชีวิตให้เว็บไซต์ เปลี่ยนหน้าเว็บที่ตายตัวให้กลายเป็นแอปพลิเคชันที่มีชีวิตชีวาและโต้ตอบได้แบบเรียลไทม์ โดยอาศัย DOM เป็นแผงควบคุมจำลอง ใช้ getElementById ล็อกเป้าหมาย แล้วเปลี่ยนแปลงเนื้อหาด้วย .innerHTML พร้อมทั้งดักจับพฤติกรรมผู้ใช้งานผ่าน Event ต่างๆ ทั้งจากเมาส์และคีย์บอร์ด เพื่อสร้างการตรวจสอบข้อมูลแบบ Real-time ที่ HTML เพียงอย่างเดียวทำไม่ได้ ก่อนก้าวเข้าสู่บทถัดไป

DOM คือกุญแจสำคัญJavaScript ไม่ได้แก้ไฟล์ HTML โดยตรง แต่ปรับแต่งผ่านแผงควบคุมจำลอง (DOM)
Event คือจุดเริ่มต้นเว็บไซต์ที่โต้ตอบได้ต้องมีตัวดักจับ (Events) คอยเฝ้ารอพฤติกรรมของผู้ใช้
UX คือเป้าหมายสูงสุดการดักจับ Validation แบบ Real-time ป้องกันข้อผิดพลาดและยกระดับความรู้สึกของผู้ใช้งานสู่ระดับมืออาชีพ
